# 一期技术方案与实现说明

## 1. 目标和边界

一期建立可独立运行的聊天闭环：浏览器提交文本，Spring Boot 持久化消息并调用 Spring AI Agent，通过 SSE 增量返回回答，最终将完整结果写入 MySQL。系统是本地单实例、单用户、无登录模式。

本期不实现 RAG、长期记忆、工具调用、多 Agent、Redis 和多实例并发。

## 2. 请求链路

1. 前端通过 REST 创建或选择会话。
2. `POST /messages/stream` 携带问题和模型 ID。
3. `GenerationRegistry` 抢占会话级生成权，重复提交直接返回 409。
4. `ChatService` 校验内容和模型，在事务中创建用户消息与 STREAMING 助手消息。
5. `CaffeineShortTermMemory` 返回最近 20 条已完成消息；缓存未命中时由 MyBatis 查询 MySQL。
6. `AgentClient` 返回 `Flux<String>`。Mock 客户端用于零配置验收，真实客户端由 Spring AI `ChatClient` 驱动。
7. `ChatStreamService` 把增量转为 SSE `delta`，在内存中拼接完整答案。
8. 正常、异常或取消时一次性更新助手消息，并释放生成注册。

## 3. 分层职责

| 模块 | 职责 |
| --- | --- |
| `conversation` | 会话/消息实体、MyBatis Mapper、事务持久化、REST |
| `chat` | 上下文缓存、生成互斥、Agent 流和 SSE 生命周期 |
| `agent` | 模型目录、Mock、Spring AI ChatClient 适配 |
| `common` | 错误码、统一响应、请求 ID |
| `ui/api` | REST 和字节安全的 SSE 帧解析 |
| `ui/hooks` | 会话、消息、生成和取消状态 |

Controller 不直接访问 Mapper，Agent 不负责数据库写入，因此后续可分别替换传输层、模型供应商和数据层。

## 4. 数据一致性

用户消息和助手占位消息在一个事务中创建，序号使用会话当前最大值顺延。流式 token 不逐个写库，避免写放大；终止时一次写完整内容。

异常退出可能留下 STREAMING 消息。应用启动后按流超时时间扫描遗留记录，标记为 `FAILED`，错误码为 `GENERATION_INTERRUPTED`。删除会话通过外键级联删除消息，并通过应用事件失效 Caffeine。

一期为单实例，`MAX(sequence_no) + 1` 和进程内生成锁满足当前边界。扩展为多实例前，需改为数据库锁或独立序列，并将生成注册迁移到分布式协调组件。

## 5. SSE 实现

浏览器 `EventSource` 只能 GET，无法携带问题 JSON，因此使用 `fetch`：

- 请求头指定 `Accept: text/event-stream`。
- `TextDecoder` 以流模式处理跨字节块的 UTF-8 中文字符。
- 解析器以空行拆分 SSE 帧，支持 `id`、`event` 和多行 `data`。
- `AbortController` 停止浏览器读取；服务端连接回调取消 Reactor subscription 并保存已生成内容。
- Nginx 关闭 `proxy_buffering` 和缓存，避免增量被聚合。

## 6. Spring AI 模型接入

`ModelCatalog` 只暴露实际可用模型。Mock 始终存在；OpenAI 兼容模型要求 enabled、base URL、API Key 和模型名完整。每个真实模型构造独立的 `OpenAiChatModel` 和 `ChatClient`，系统提示词作为 Spring AI `SystemMessage` 注入，历史角色映射为 `UserMessage` 或 `AssistantMessage`。

Spring AI 的 OpenAI 自动配置被关闭，由项目显式创建模型客户端。这样 Mock-only 启动不会因为缺少 API Key 失败。

## 7. 部署

Compose 包含：

- `mysql`：持久卷、健康检查。
- `server`：等待 MySQL 健康后启动，Flyway 自动迁移。
- `ui`：多阶段构建静态资源，由 Nginx 提供 SPA fallback 和 API/SSE 反代。

密钥只经 `.env` 注入；模板文件不包含真实凭证。

## 8. 后续演进

- 二期如需知识增强，在 Agent 输入前新增检索模块，不改变 SSE 协议。
- 多实例部署需引入分布式生成锁、会话序列和共享取消信号。
- 长回答可增加 token 预算、上下文摘要和按模型窗口截断。
- 生产部署需增加认证、限流、HTTPS、数据库备份和可观测性。
