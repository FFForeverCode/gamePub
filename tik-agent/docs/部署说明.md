# tik-agent 一期部署说明

## 1. 部署范围

一期只支持本地 Docker 部署。Compose 同时运行 Nginx 前端、Spring Boot 后端和 MySQL 8.4，不包含公网域名、HTTPS、多副本或云托管。

## 2. 环境准备

- Docker Desktop 4.x 或 Docker Engine 24+
- Docker Compose v2
- 可用端口：`5173`、`8080`、`3306`

从模板创建本地配置：

```bash
cp .env.example .env
```

默认 Mock 模式不需要模型密钥。

## 3. 启动与检查

```bash
docker compose up --build -d
docker compose ps
curl -fsS http://localhost:8080/actuator/health
```

健康检查返回 `{"status":"UP"}` 后，打开 <http://localhost:5173>。

查看日志：

```bash
docker compose logs -f server
docker compose logs -f ui
docker compose logs -f mysql
```

执行完整 Mock 流程：

```bash
./scripts/perf-smoke.sh
```

## 4. 数据持久化

MySQL 的 `/var/lib/mysql` 映射到名为 `tik-agent-mysql` 的 Docker volume。普通 `docker compose down` 不会删除历史。备份或迁移前应停写并导出数据库。

清空本地数据会永久删除历史：

```bash
docker compose down -v
```

## 5. 模型配置

OpenAI 兼容端点需要：

```dotenv
TIK_AGENT_DEFAULT_MODEL=openai
TIK_AGENT_OPENAI_ENABLED=true
TIK_AGENT_OPENAI_BASE_URL=https://api.openai.com/v1
TIK_AGENT_OPENAI_API_KEY=...
TIK_AGENT_OPENAI_MODEL_NAME=gpt-4.1-mini
```

修改后运行 `docker compose up --build -d server`。不要提交 `.env`。

## 6. 故障排查

| 现象 | 检查 |
| --- | --- |
| server 等待 MySQL | `docker compose ps` 查看 MySQL health |
| 端口占用 | 修改 `.env` 的 `UI_PORT`、`SERVER_PORT`、`MYSQL_PORT` |
| SSE 一次性出现 | 确认请求经过仓库内 `nginx.conf`，且 `proxy_buffering off` |
| 模型列表只有 Mock | 检查 OpenAI 配置是否完整并重启 server |
| Flyway 启动失败 | 检查数据库账户权限及已有 schema 是否由 Flyway 管理 |
